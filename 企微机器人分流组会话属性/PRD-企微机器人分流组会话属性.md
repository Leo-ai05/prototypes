## 二、需求概述

- **背景**：用户被分配到分流组后，当前会话属性中没有保存该分流组标识。
- **目标**：在「基础信息」中新增「所属分流组」会话属性，保存用户分配到的分流组 ID。
- **核心规则**：用户首次分配成功后写入分流组 ID；写入成功后固定保存，不再修改。

## 三、调整范围

| 功能模块 | 调整类型 | 说明 |
|---|---|---|
| 会话属性-基础信息 | 新增 | 新增系统预设属性「所属分流组」 |
| 用户分流写入 | 新增 | 用户分配成功后写入分流组 ID |

## 四、功能需求

### 4.1 新增会话属性

**所在位置**：企业微信机器人 → 会话属性 → 基础信息

| 配置项 | 要求 |
|---|---|
| 属性名称 | 所属分流组 |
| 属性分类 | 基础信息 |
| 属性类型 | 字符串 |
| 属性值 | 用户所属分流组的 ID |
| 属性来源 | 系统分流结果 |
| 修改权限 | 只读，不允许人工或其他业务流程修改 |

### 4.2 属性写入

1. 用户尚未分配分流组时，该属性为空。
2. 用户首次分配成功后，系统将分流组 ID 写入「所属分流组」。
3. 写入成功后，该值固定保存。
4. 用户后续再次触发分流判断时，系统直接沿用已保存的分流组 ID，不重复分配、不覆盖原值。
5. 同一用户并发触发分配时，只允许首次成功写入生效。
6. 写入失败时不保存错误值，并记录异常；后续可重新尝试写入。

## 五、不在本需求范围

- 不展示或同步分流组名称。
- 不提供分流组动态枚举。
- 不新增规则条件、话术变量或扣子同步能力。
- 不处理存量用户批量补值。
- 不调整分流开关、分流比例及分流组配置逻辑。
- 不新增报表、埋点或独立页面。

## 六、验收标准

1. 会话属性「基础信息」中存在「所属分流组」。
2. 用户分配成功后，属性值与实际分配的分流组 ID 一致。
3. 已有属性值不会被后续分流判断或人工操作修改。
4. 未分配用户的属性值为空。
5. 并发分配不会产生多个或被覆盖的分流组 ID。
